# Container registration token tests

The six official entrypoints put plaintext `BUILDKITE_AGENT_TOKEN` values in a
pipe, wait for its writer to exit, and re-exec Bash before running startup
scripts. Tini remains PID 1. The agent drains and closes the dedicated handoff
at process startup, before command parsing, even when a CLI token overrides it.
The value stays in agent memory for token resolution; it is never restored to
the environment. Parent processes retain only the empty read end by job-ready
time, including when running `bootstrap` directly.

Plaintext environment tokens are limited to 4096 bytes so waiting for the writer
cannot deadlock on pipe capacity. This also applies to help and invalid commands.
Process substitution is intentional: older Bash versions can back here-strings
with recoverable temporary files.

Startup scripts receive an `fd://` reference instead of the plaintext token.
The reference is single-use: scripts must not drain it or persist it as a token
file. The dedicated consumption marker is withheld from `run-parts`, so startup
scripts can still invoke commands such as `buildkite-agent --version` without
consuming the final agent's handoff. Scripts that need their own registration
token must supply it separately.

An image-only launcher protects actual `start --token` arguments before startup
scripts run. It uses the agent's flag definitions exported at build time and the
same argument parser as standalone token scrubbing. Duplicate flags retain
last-value precedence; token-looking flag values and positional arguments remain
untouched. The launcher re-execs the entrypoint with token references, which then
runs startup scripts and execs tini as before.

Literal CLI tokens and effective CLI `fd://` inputs use a separate pipe, limited
to 4096 bytes. FD inputs count all bytes before trimming leading and trailing
whitespace. Byte 4097 causes rejection without waiting for the writer to close.
Inputs of at most 4096 bytes still wait for their producer and EOF, as the agent's
FD resolver already did; a writer that never closes can therefore keep startup
waiting. The agent drains the handoff pipe before registration.
Only actual CLI token descriptors are closed; the dedicated environment pipe
and marker stay intact. A CLI reference to that same environment descriptor uses
the agent's startup cache rather than reading twice. Help and argument errors
skip token reads. Operator-managed `file://` inputs are passed through, including
files generated by startup scripts. Persistent token files are not removed.

Run from the repository root against a built image:

```sh
BUILDKITE_TEST_CONTAINER_IMAGE=local-agent-image go test -count=1 -v ./internal/containerimage
```

For cached fixtures, `BUILDKITE_TEST_CONTAINER_BINARY`,
`BUILDKITE_TEST_CONTAINER_HELPER`, and `BUILDKITE_TEST_CONTAINER_ENTRYPOINT`
accept absolute paths to the Linux agent, image launcher, and real entrypoint
script. `BUILDKITE_TEST_CONTAINER_ARCH` selects
the container architecture, defaulting to the host architecture.

The suite uses dummy tokens and a loopback fake API with `--network=none`.
It checks authenticated registration and polling, startup-process environments,
recoverable regular descriptors, both drained parent pipes, SSH setup, orphan
reaping, SIGTERM forwarding, CLI precedence, help/error exits, size limits, and
direct bootstrap execution. Inspection failures terminate the fixture immediately:
a failed read must not drain the pipe and allow a later poll to pass.

Image CI builds the launcher and a test-only executable alongside the Linux agent
artifacts. The six agent images contain the launcher; normal agent archives and
installers do not. The test executable runs against each image without being
packaged into it.

The six helper images require agent and helper artifacts built from the same
source in the same CI build. `build-docker-image.sh` rejects a nonempty version
argument for these images before downloading or changing files. A matching
version string alone cannot establish source identity or environment-handoff
compatibility. Downloaded-version builds remain available for sidecar images.
